The compiler packages enable zero-allocation database pushdown, allowing your database engine to evaluate rules before records are loaded into Node.js memory.

---

## 1. `compileToSQL(rule, options?)`

Compiles a rule AST into a valid SQL `WHERE` clause expression:

```ts
import { compileToSQL, rule } from "@qarar/sdk";

const myRule = rule("Active VIPs")
  .where("customer.age").gte(18)
  .and("customer.tier").in(["gold", "vip"])
  .build();

const { sql } = compileToSQL(myRule, { columnStyle: "snake" });

console.log(sql);
// ➔ customer_age >= 18 AND customer_tier IN ('gold', 'vip')
```

### Options

| Option | Type | Default | Description |
| :--- | :--- | :--- | :--- |
| `columnStyle` | `"snake" \| "path" \| "quote"` | `"snake"` | How nested field paths are formatted into column names. |

- **`"snake"`**: Converts dots to underscores (`customer_age`).
- **`"path"`**: Preserves dot notation for JSONB paths or table aliases (`customer.age`).
- **`"quote"`**: Double-quotes each path segment (`"customer"."age"`).

### Performance
- **Throughput**: **~639,652 compiles/second**
- **Average Latency**: **1.56 µs**

## 2. `compileToMongo(rule)`

Compiles a rule AST into a standard MongoDB filter object:

```ts
import { compileToMongo, rule } from "@qarar/sdk";

const myRule = rule("Active VIPs")
  .where("customer.age").gte(18)
  .and("customer.tier").in(["gold", "vip"])
  .build();

const { filter } = compileToMongo(myRule);

console.log(JSON.stringify(filter, null, 2));
/*
{
  "$and": [
    { "customer.age": { "$gte": 18 } },
    { "customer.tier": { "$in": ["gold", "vip"] } }
  ]
}
*/
```

### Performance
- **Throughput**: **~1,339,871 compiles/second**
- **Average Latency**: **0.75 µs**
