The fluent builder APIs (`rule()` and `switchRule()`) provide full TypeScript autocompletion and schema validation, allowing you to construct rules programmatically without writing raw JSON AST nodes by hand.

---

## 1. `rule(nameOrId?)`

Initializes a new `RuleBuilder` instance:

```ts
import { rule } from "@qarar/sdk";

const myRule = rule("Customer Eligibility Gate")
  .id("rule_101")
  .description("Verifies user age and subscription tier")
  .version("1.2")
  .where("customer.age").gte(18)
  .and("customer.tier").in(["gold", "vip"])
  .build();
```

### Metadata Methods
- **`.id(id: string)`**: Sets the unique rule identifier.
- **`.name(name: string)`**: Sets a human-readable title.
- **`.description(desc: string)`**: Sets an optional descriptive summary.
- **`.version(ver: string)`**: Sets the version string (defaults to `"1"`).

### Condition Chaining Methods
- **`.where(fieldPath | condition)`**: Starts the root condition chain.
- **`.and(fieldPath | condition)`**: Adds an `AND` condition.
- **`.or(fieldPath | condition)`**: Adds an `OR` condition.
- **`.not(condition)`**: Adds an inverted `NOT` condition.

### Comparison Operator Methods
When calling `.where("field.path")`, `.and("field.path")`, or `.or("field.path")`, a condition builder is returned:

| Method | Description | Example |
| :--- | :--- | :--- |
| **`.eq(value)`** | Strict equality | `.where("status").eq("active")` |
| **`.neq(value)`** | Strict inequality | `.where("country").neq("RESTRICTED")` |
| **`.gt(number)`** | Greater than | `.where("cart.total").gt(50)` |
| **`.gte(number)`** | Greater than or equal | `.where("customer.age").gte(18)` |
| **`.lt(number)`** | Less than | `.where("risk.score").lt(300)` |
| **`.lte(number)`** | Less than or equal | `.where("attempts").lte(3)` |
| **`.in(values)`** | Set membership | `.where("tier").in(["gold", "vip"])` |
| **`.notIn(values)`** | Set non-membership | `.where("role").notIn(["guest", "bot"])` |
| **`.between(min, max)`**| Range inclusion (inclusive) | `.where("age").between(18, 65)` |
| **`.contains(value)`** | Substring / array inclusion | `.where("tags").contains("promo")` |
| **`.startsWith(prefix)`**| String prefix match | `.where("sku").startsWith("PROMO-")` |
| **`.endsWith(suffix)`** | String suffix match | `.where("email").endsWith("@company.com")` |
| **`.matches(regex)`** | Regex pattern test | `.where("code").matches("^[A-Z]{4}-\\d{4}$")` |
| **`.isNull()`** | Null or undefined check | `.where("deletedAt").isNull()` |
| **`.isNotNull()`** | Non-null/defined check | `.where("verifiedAt").isNotNull()` |

## 2. Nested Condition Groups

To construct nested boolean logic like `(A AND B) OR (C AND D)`, pass a nested `rule()` builder directly into `.or()` or `.and()`:

```ts
const complexRule = rule("Fraud Shield")
  .where("risk.score").gte(700)
  .or(
    rule()
      .where("transaction.amount").gte(5000)
      .and("risk.isNewDevice").eq(true)
  )
  .build();
```

## 3. `switchRule<TOutput>(nameOrId?)`

Initializes a `DecisionTableBuilder` for multi-branch routing with typed outputs:

```ts
import { switchRule } from "@qarar/sdk";

interface TierOutput {
  discount: number;
  freeShipping: boolean;
}

const pricingTable = switchRule<TierOutput>("Tier Pricing")
  .default({ discount: 0, freeShipping: false })
  .mode("first") // "first" (early exit) or "all" (multi-match)
  .case("vip", { discount: 25, freeShipping: true }, (c) =>
    c.where("tier").eq("vip").and("total").gte(200)
  )
  .case("gold", { discount: 15, freeShipping: true }, (c) =>
    c.where("tier").eq("gold").and("total").gte(100)
  )
  .build();
```
