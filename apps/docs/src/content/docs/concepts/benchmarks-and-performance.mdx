When you evaluate business rules on every incoming API request or Kafka message, the rule engine shouldn't be the bottleneck.

We built `@qarar/benchmark` as an open benchmark suite inside the monorepo so anyone can run the tests locally and verify the numbers. Below are the actual measurements from running 100,000 iterations per test on a standard Apple Silicon development machine.

---

## Practical Takeaways

### 1. `compileRule()` vs `evaluate()`
If you evaluate the same rule repeatedly (for instance, inside an Express route, a Next.js action, or a stream consumer), use `compileRule()` once when your service starts:

```ts
import { compileRule, rule } from "@qarar/sdk";

// Compile once at startup
const isVipEligible = compileRule(
  rule("VIP Policy")
    .where("user.age").gte(18)
    .and("user.tier").in(["vip", "platinum"])
    .build()
);

// Runs in ~80 nanoseconds on the hot path (6M+ ops/sec)
app.post("/checkout", (req, res) => {
  const eligible = isVipEligible(req.body);
  // ...
});
```

`compileRule()` builds a direct JavaScript closure from your rule tree. This skips walking the AST object on every call and gives you an extra 15% to 20% throughput.

### 2. Large Datasets (100,000 Records)
When filtering an array of 100,000 JSON records in memory:
- Total time to evaluate all 100,000 items: **~34.5 milliseconds**.
- Memory: The runner monitors heap usage before and after. Because evaluation reads properties directly without creating new objects per check, heap memory stays flat with no GC pauses.

### 3. Array & Date Checks
- **Array operations** (`arrayContains`, `some`, `every`, `length`): Average **0.27 µs**. The engine iterates through the target array directly and stops as soon as a condition matches or fails.
- **Date comparisons**: Average **0.76 µs**. The engine converts ISO 8601 strings and Epoch numbers to UTC milliseconds and does numeric subtraction. No heavy date libraries or polyfills are loaded.
- **Two-sided dynamic fields** (`{{ customer.creditLimit }}`): Average **0.55 µs**. The engine resolves both field paths on the incoming payload in a single lookup pass.

### 4. Database Pushdown
Translating a rule AST into a SQL `WHERE` string or a MongoDB query object takes under 1 microsecond. You can compile rules on the fly before querying your database without caching the query string.

## Run the Benchmarks Locally

You can run the exact benchmark suite on your own machine:

```bash
# Clone the repository
git clone https://github.com/mshehata-dev/qarar.git
cd qarar
pnpm install
pnpm build

# Run in-memory microbenchmarks (100k iterations per test)
pnpm --filter @qarar/benchmark bench:micro

# Run 100,000-row dataset stress test
pnpm --filter @qarar/benchmark bench:dataset

# Run decision table multi-branch benchmark
pnpm --filter @qarar/benchmark bench:decision
```
