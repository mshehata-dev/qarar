SaaS businesses need to gate premium features, restrict team seat counts, and enforce rate limits according to subscription plans. When pricing tiers change or marketing runs a trial promotion, entitlement rules shouldn't require code changes.

This recipe demonstrates defining entitlement rules, evaluating user access, and presenting actionable upgrade prompts.

---

## 1. Entitlement Rule Definition

Grant access to Advanced Analytics if:
- User is an `"owner"` or `"admin"`, **OR**
- Organization is on the `"pro"` or `"enterprise"` plan and within active seat quotas.

```ts
import { rule, checkRule } from "@qarar/sdk";

export const analyticsAccessRule = rule("Advanced Analytics Feature Gate")
  .id("entitlement_analytics_v1")
  .where("user.role").in(["owner", "admin"])
  .or(
    rule()
      .where("org.plan").in(["pro", "enterprise"])
      .and("org.seatsUsed").lte(100)
      .and("org.subscriptionStatus").eq("active")
  )
  .build();
```

## 2. In-Memory Route Guard & Paywall Trigger

Protect API endpoints and generate upgrade banners for free or restricted users:

```ts
import { checkRule } from "@qarar/sdk";

export function checkFeatureAccess(userContext: Record<string, unknown>) {
  const check = checkRule(analyticsAccessRule, userContext);

  if (!check.result) {
    return {
      allowed: false,
      upgradeRequired: true,
      message: "Upgrade to Pro to unlock Advanced Analytics.",
      reasons: check.reasons,
    };
  }

  return { allowed: true };
}

// Example: Free user trying to export an analytics report
const freeUser = {
  user: { role: "member" },
  org: { plan: "starter", seatsUsed: 5, subscriptionStatus: "active" },
};

const access = checkFeatureAccess(freeUser);
console.log(access.allowed); // false
console.log(access.message); // "Upgrade to Pro to unlock Advanced Analytics."
```
